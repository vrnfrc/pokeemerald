# Editing data in pokeemerald

Most data lives in **hand-written C headers** under `src/data/`. A small subset is **JSON-driven** — edit the JSON and the build regenerates the headers/constants (see `json_data_rules.mk`, `map_data_rules.mk`; re-run `make` after editing).

## Pokémon (`src/data/pokemon/`)

| File | Contents |
|---|---|
| `species_info.h` | Base stats, types, abilities, catch rate, EXP yield, egg groups, gender ratio, etc. |
| `evolution.h` | Evolution conditions |
| `level_up_learnsets.h` (+ `level_up_learnset_pointers.h`) | Level-up movesets |
| `tmhm_learnsets.h` | TM/HM compatibility |
| `tutor_learnsets.h` | Move tutor compatibility |
| `egg_moves.h` | Egg moves |
| `experience_tables.h` | EXP curves |
| `pokedex_entries.h`, `pokedex_orders.h`, `pokedex_text.h` | Pokédex data |
| `cry_ids.h` | Cries |

Related tables elsewhere: `src/data/items.h`, `src/data/battle_moves.h`, `src/data/contest_moves.h`.

## Trainers

- `src/data/trainers.h` — class, party size, sprite, palette, etc.
- `src/data/trainer_parties.h` — actual party data (species, moves, items, EVs/IVs).
- `src/data/battle_frontier/` — Battle Frontier trainer data.

## JSON-driven datasets (do not hand-edit the generated headers)

| Source JSON | Generated by | Outputs |
|---|---|---|
| `src/data/wild_encounters.json` | `jsonproc` | `src/data/wild_encounters.h`, `include/constants/wild_encounter.h` |
| `src/data/heal_locations.json` | `jsonproc` | `src/data/heal_locations.h`, `include/constants/heal_locations.h` |
| `src/data/region_map/region_map_sections.json` | `jsonproc` | `src/data/region_map/region_map_entries.h`, `include/constants/region_map_sections.h` |
| `data/maps/*/map.json` + `data/maps/map_groups.json` | `mapjson` | per-map `header.inc` / `events.inc` / `connections.inc`, plus `data/maps/headers.inc`, `groups.inc`, `events.inc`, `connections.inc`, `include/constants/map_groups.h`, `include/constants/map_event_ids.h` |
| `data/layouts/layouts.json` | `mapjson` | `data/layouts/layouts.inc`, `data/layouts/layouts_table.inc`, `include/constants/layouts.h` |

The `.json.txt` / `.constants.json.txt` files alongside each source JSON are Inja templates — only touch them if you change the JSON schema.

## Maps and layouts

- Map properties (header, events, connections): edit `data/maps/<MapName>/map.json`.
- Adding a new map: also add an entry in `data/maps/map_groups.json` and a layout in `data/layouts/`.
- Layouts (tilemap, width/height, blockset): `data/layouts/<LayoutName>/` (binary assets consumed by `mapjson`).

## Other things you may need to edit

- Items: `src/data/items.h`.
- Moves (battle): `src/data/battle_moves.h`; (contest): `src/data/contest_moves.h`.
- Abilities: `include/constants/abilities.h` (id list) and the ability definitions in `src/data/`.
- Items effects: `src/data/items.h` and per-item logic in `src/item_use.c` / `src/item.c`.
- Music: data-driven via `sound/songs/midi/midi.cfg` and the `.mid` files in `sound/songs/midi/`. Each `.mid` listed in `midi.cfg` becomes a `mid2agb` rule.
- Graphics: PNG/PAL sources under `graphics/...` are converted by `gbagfx` to `.4bpp` / `.gbapal` / `.lz` / `.rl` at build time.

## When something doesn't seem to take effect

1. Is the file JSON-driven? If yes, the `.h`/`.inc` is regenerated — never hand-edit it.
2. For maps, also check `data/maps/map_groups.json` (group/order) and `data/layouts/layouts.json` (layout assignment).
3. For music, missing `midi.cfg` entry → build warns and fails at link time.
4. Run `make clean` and rebuild if generated files look stale.
